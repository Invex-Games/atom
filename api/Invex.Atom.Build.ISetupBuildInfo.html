Examples

While SetupBuildInfo is often implicitly part of a default build definition, here's how a custom target can depend on it and consume the variables it produces. Variables are consumed via the corresponding build parameters (declared with ConsumesVariable(string, string) and read with GetParam). 

// In a target interface within your Atom build project
public interface IPackage : ISetupBuildInfo
{
    Target Package => t => t
        .DependsOn(nameof(ISetupBuildInfo.SetupBuildInfo)) // Ensures build info is set up
        .ConsumesVariable(nameof(ISetupBuildInfo.SetupBuildInfo), nameof(BuildVersion))
        .Executes(() =>
        {
            // BuildVersion is resolved from the variable written by SetupBuildInfo
            Logger.LogInformation("Packaging {Name} version {Version}", BuildName, BuildVersion);
            // ... further packaging logic ...
        });
}
// To run this build (assuming Atom CLI):
// atom Package

Remarks

The SetupBuildInfo target is a foundational step in the Atom build pipeline. It performs several key actions: 

<ul><li>
            Retrieves the build name (from <xref href="Invex.Atom.Build.BuildInfo.IBuildInfo.BuildName" data-throw-if-not-resolved="false"></xref>) and writes it as a build
            variable named
            "BuildName".
        </li><li>
            Retrieves the build ID (from <xref href="Invex.Atom.Build.BuildInfo.IBuildInfo.BuildId" data-throw-if-not-resolved="false"></xref>) and writes it as a build variable
            named "BuildId".
        </li><li>
            Retrieves the build version (from <xref href="Invex.Atom.Build.BuildInfo.IBuildInfo.BuildVersion" data-throw-if-not-resolved="false"></xref>) and writes it as a build
            variable
            named
            "BuildVersion".
        </li><li>
            Retrieves the build timestamp (from <xref href="Invex.Atom.Build.BuildInfo.IBuildInfo.BuildTimestamp" data-throw-if-not-resolved="false"></xref>), converts it to a
            string,
            and
            writes it
            as a build variable named "BuildTimestamp".
        </li><li>
            Adds a "Run Information" section to the build report, displaying the build name, version,
            ID, and timestamp.
        </li><li>
            Logs the build ID, version, and timestamp using the configured logger for
            <code>ISetupBuildInfo</code>.
        </li></ul>

This target is marked as hidden (IsHidden()), meaning it's not typically intended for direct invocation by users but is expected to run as a dependency for other targets or as part of an initial setup sequence.

It produces the following build variables, which can be consumed by subsequent targets in the build process: 

<ul><li><span class="term">
            <code>BuildName</code>
        </span>The name of the build.</li><li><span class="term">
            <code>BuildId</code>
        </span>The unique identifier for the build execution.</li><li><span class="term">
            <code>BuildVersion</code>
        </span>The version of the software being built.</li><li><span class="term">
            <code>BuildTimestamp</code>
        </span>The timestamp of the build (as a string).</li></ul>

Successful execution relies on the correct registration and functioning of IBuildIdProvider, IBuildVersionProvider, and IBuildTimestampProvider services within the Atom framework.
